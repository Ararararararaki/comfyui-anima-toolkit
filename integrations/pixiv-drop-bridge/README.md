# TK → Pixiv 图片接收桥 0.2.0

将 TK Toolkit 的 Outputs 图片或预览中的“拖出当前图”交给 Pixiv 添加图片区域。免填地址和 API Key；扩展跟随实际拖出页面的本机端口。

## 安装与使用

1. 解压扩展压缩包，保留在固定文件夹。Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`。
2. 开启“开发者模式”，点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的文件夹。首次安装需要这一步，这是浏览器安全规则，工具箱无法代为安装。
3. **工具箱和 Pixiv 投稿页两端都要刷新。** 两个页面须在同一浏览器、同一用户资料中；Pixiv 有图片上传控件时，右下角会出现“TK 图片接收桥”。更新扩展后也要在扩展页重新加载，再刷新两端。
4. 在 Outputs 图片上停留片刻，或使用预览的“拖出当前图”。副本准备好后直接拖到 Pixiv 添加图片区域或接收桥框内。
5. 若跨标签页拖拽没有触发接收，先在工具箱拖动图片一下，再回 Pixiv 点击“接收刚拖出的图片”。请确认 **Pixiv 自身生成图片预览**；投稿由你操作。

## 支持范围

- 面向 Chrome / Edge 的 Manifest V3 扩展。工具箱使用本机 HTTP `localhost` 或 `127.0.0.1`，支持 1–65535 的有效端口（含默认 80），无需修改扩展；不支持远程服务器、局域网地址、HTTPS 工具箱或其他浏览器。
- 一次接收一张，单张上限 32 MiB；只保留最近一次拖出的票据，90 秒失效，读取超时 20 秒。浏览器重启或扩展后台休眠后需重新拖动。
- 只读取同源 `/anima/gallery/share` 的受校验分享地址，不读取任意文件或其他本地服务；网站范围仅 `https://www.pixiv.net`。出现多个可用图片上传控件时会停止，避免选错目标。
- 图片字节遵循 Toolkit 的全局元数据设置，包括清除元数据、保留元数据与署名。扩展转交最终导出字节，不另行改写；“已交给上传控件”不等于投稿成功。
- 不保存图片到扩展存储、不读取账号密码、不自动投稿。停用扩展即可恢复原浏览器行为，无需重启 ComfyUI。

0.1.0 曾由用户确认 Chrome / Pixiv 实站接收成功；0.2.0 的任意端口与拒绝规则由本地离线回归验证，未追加真实 Edge 或 Pixiv 实站验收。网站更新可能需要适配。
