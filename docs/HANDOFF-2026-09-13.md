## 2. 画廊：改了什么（含实测数字）

### 2.1 ⭐ 布局从「CSS Grid 行跨」换成「列填充 + 跨列」（真正的瀑布流）

旧实现是 `grid-template-columns: repeat(auto-fill, minmax(150px,1fr))` + JS 写
`grid-row-end: span N`（按 `card.scrollHeight` 算）。实测两个硬伤：

- **卡片宽度恒等于列宽**：1298px 宽的网格 8 列 → 每张卡只有 **156px**；节点再宽也只是列数变多、图越小；
- **行内高矮不一会留成片空白**：48 张卡在 1298×1438 里底部空 **106px**，行间还有洞。

新实现（移植面板 Outputs 的 masonry 算法到节点）：

- 逐张放进**当前最矮的列**；超宽图（盒比 ≤0.45）跨 2 列、≤0.25 跨 3 列；
- 卡片改**绝对定位**（`left/top/width/height` 由 JS 写死），容器只负责滚动 + `min-height`；
- 图片 `object-fit: cover`（`contain` 会按比例留黑边，旧实现因此总在窄卡里出现竖图被压扁的观感）。

**实测（`verify-dg-waterfall.cjs`，1600×1000 视口，DPR1）**：

| 指标 | 旧 | 新 |
|---|---|---|
| 底部余量 | 106px | **9px** |
| 右侧余量 | — | **3px** |
| 重叠 | — | **0** |
| 可用宽度是否吃满 | 否 | 是（10 列 × 123px + 跨列卡 253px） |

### 2.2 ⭐ 三个踩坑（不要重犯）

1. **滚动条会让 `clientWidth` 变小** → `applyMasonryLayout` 算出的宽度比之后重新测量的可用宽度大十几像素 → 卡片宽出容器 → 出现**横向滚动条**（实测 rightEdge 1295 > 可用 1283）。
   修法：记住上次的**列步长** `lastColStep`，下次按「可用宽 ÷ 列步长」**取整反推列数**，而不是重新除一遍最小列宽。
2. **`js.index('saveSettings()')` 命中的是调用点而不是定义** → 新增 `discoverRandom` 后 `test_danbooru_gallery_settings_scope.py` 误报。
   修法：测试锚定 `"\n    saveSettings() {"`。**教训：静态断言必须锚定定义/签名，不能用裸子串。**
3. **`web/` 目录里的备份文件会被 ComfyUI 当扩展一起加载** → 浏览器加载了两份 widget，`registerExtension` 跑两次，
   **工具栏出现两组随机按钮**、网格出现两个（探针 `check-module-fresh.cjs` 抓到的）。
   修法：备份移出 `web/`（移到插件根 `_bak_dg_waterfall_20260913/`），顺手清掉 `web/js/*.backup-*`。
   **铁律：`web/` 是「会被服务出去」的目录，任何 `.js` 备份/实验文件都必须放在它外面。**

### 2.3 随机发现：产品设计决策（有实测依据）

- **实测**：`order:random score:>100 age:<30days` → **0 结果**；`order:random score:>100` → 48 结果。
  时间窗会把随机池掐死，所以**三档都不带 age 窗**，靠**分数/收藏地板**保证「有人贴过」。
- **实测**：`miku_day`（星期几标签）全站只有 31 张满足 score>100 → 一页 48 就把池子取光。
  因此「换一批」会检测**是否真的换出了新图**，没有就明确提示「这一档能给的都看过了」，而不是假装换过。
- 内容标签 ∩ 随机池可能为空（`miku_day score:>100 age:<30days`=0）→ 自动**退化为纯随机**并说明；
  两轮都失败则**回滚设置**，不让用户卡在空网格里。
- `force=1` 必带：不带会命中后端 30s 缓存，给出**完全相同**的一批，"随机"就名存实亡。

### 2.4 顺带修掉的真 bug：排序不占计数槽（长期潜伏）

`order` 曾被加进 `FREE_METATAGS`（那是给 `presetTagParts` 判断「是不是标签」用的），
导致 `countedSearchTerms` 把排序当免费 → 计数永不超限 →「自动移除排序」分支与其提示条**变成死代码**。
`tests/test_danbooru_gallery_interactions.py` 自 **2026-09-07**（commit `a4291e0`）起一直是红的，
却被 HANDOFF 记成「预存在失败，非本轮引入」。**修完后该测试已 PASS。**

修法：拆成两个语义 —— `FREE_METATAGS`（是不是标签）与 `FREE_METATAGS_THAT_STILL_COUNT`（占不占槽），
后端 `count_restricted_search_tags` 本来就把 order 算 1 槽，现在前后端一致了。

同时修掉**查询词重复拼词**：搜索框里若残留 `rating:g` / `-filetype:mp4`（历史写入），
会与筛选面板各拼一次 → 白占计数槽、还会让「退化重试」拿到一模一样的查询而形同没重试。
现在加了 `stripFilterOwnedTokens()`：筛选面板是这些 token 的唯一 owner
（与 `order:` 早有的规矩一致），并加了大小写不敏感去重。

## 3. Outputs：生成完就自动更新

老实现的问题：`triggerOutputsIncrementalScan()` **在不显示 Outputs 时直接 return**，
所以离开页面期间生成的图不会被发现。

现在两条链：

1. **ComfyUI 执行事件**：`api.addEventListener('executed' | 'execution_success' | 'execution_cached')`
   → 延迟 2.5s（等文件确实落盘）后探测；
2. **兜底**：原有 60s 轮询 + 窗口获焦/可见性变化。

并且**隐藏时也探测/扫描**（只在不显示时才跳过重渲染）。

新增后端 `GET /anima/gallery/fresh`：**只遍历输出目录文件名并 stat**，返回
`{latest, count, known, changed, building}`；`changed` = 文件数比索引 `total` 多。
发现新增且没在建索引时顺手起一次后台增量建索引（幂等）。
**该端点不解析任何 PNG、不返回 16.5MB 索引**，所以可以放心高频轮询。

前端 `probeOutputsGrew()` 连续失败 3 次就停（老插件没有该端点时不再每轮吃 404），
静默退回「切页刷新」的旧行为。

**`panel/package.json` 的 `version` 为什么不改**：它是 `"private": true` 的内部 Vite 工程包版本
（依赖版本在 `panel/package-lock.json` 里同步），**不代表插件版本**，节点「检查更新」也不读它。
它从 2.0.0 起就没动过、也没人拿它当版本依据 —— 强行同步成插件版本只会制造「改了它却什么都没变」的假动作。
**如果以后要让它代表插件版本**，必须同时：① 在 `build:comfyui` 里把它烤进面板 UI；
② 在 `ai_verify` 里断言 —— 否则就是纯装饰。**当前结论：不要机械同步。**

`tests/ai_verify.py` 新增两项检查：

- `版本一致性（VERSION / __version__ / README / CHANGELOG）`：任一处不一致即 FAIL；并断言
  `__init__.py` 确实在**运行时读 VERSION**（防止有人把硬编码改回来）；
- `文档内版本引用无过期`：只扫 `README.md` / `docs/FEATURES.md` 里**「当前版本」语义**的句子，
  历史版本段落（CHANGELOG/HANDOFF/ADR）**不算过期**——那些数字本来就该是旧的。

**负向测试已跑**（`.workbuddy/tmp/negtest_version_drift.py`）：把 README 改回 2.9.0 → exit 1 且两处 FAIL；
还原 → exit 0。

**顺带修掉一个自检工具自身的崩溃**：`ai_verify.py` 里用了 `❌` / `⚠️`，
在默认 GBK 控制台下 `print` 会抛 `UnicodeEncodeError` —— 也就是**只在「有 FAIL 要报」时才崩**。
已替换为 `[X]` / `[!]`。（教训：诊断工具的输出编码也要当兼容性处理。）

**方法论（本轮血泪，务必遵守）**：

1. **测试要清 localStorage**：节点设置按 `anima_danbooru_gallery_settings_v2:<nodeId>` 持久化，
   跨轮次会互相污染（limit/order/randomQuality 全是持久化的），否则你会追一个不存在的 bug。
   用 `page.addInitScript(() => localStorage.clear())`。
2. **`loadGraphData` 的 resolve ≠ 节点已实例化**：轮询到目标节点真的出现再继续，
   否则偶发 `Cannot read properties of undefined (reading 'pos')`。
3. **一个页面可能同时加载多份同名扩展**（见 §2.2 第 3 条）。探针里先删到只剩一个画廊节点再统计，
   否则「按钮×6」「网格×2」这类假象会骗你半小时。
4. **`miku_day` 这类内容标签会让随机池变空**，别把它当成随机功能坏了 —— 先用
   `Invoke-WebRequest` 直打 `/anima/danbooru/posts` 把查询串逐个变量分离开来验证。
