## B. 确定存在的问题（证据充分）

### B1 ⚠️ 版本漂移（**已修**，保留记录）
README 停在 2.9.0 而 `VERSION` 已 2.10.0；`docs/FEATURES.md` 残留「版本 v0.4」。
根因不是「忘了同步」，而是**设计上有两个真源**（`VERSION` + 硬编码 `__version__`）。
→ 已改为运行时读 `VERSION`，并让 `ai_verify` 在漂移时 FAIL（负向测试通过）。

### B2 ⚠️ CI 完全缺验证，且 build bot 有循环风险
- `Build panel app` 在 push 到 main 且改 `panel/**` 时执行 `npm ci` + 构建 + **由 bot 提交 `app/`**。
  若再让「验证型 CI」也在 push 时跑并产出，容易互相触发；且 bot 提交本身会再次触发 push 事件链。
- **没有任何 Python / 测试 / 类型检查校验**，PR 合入一个编译不过的改动 → bot 构建失败 → `app/` **静默停在旧版**。
- 已有 `ai_verify.py` 是现成的「一步全量自检」，却**没有接进 CI**。

### B3 ⚠️ `tests/` 没有分层，且「需要真实浏览器 + ComfyUI 在线」的脚本混在 pytest 里
- `ai_verify.py` 把自己算作 pytest 收集对象（名字不含 test，实际不会被收，但目录里同类脚本命名不一致）。
- `verify_*.py` 多数 `assert` 在模块顶层（无 `__main__` 守卫）→ 被 pytest 收集时会**在收集阶段就执行**，
  需要真实浏览器/8188 在线，CI 里必然失败或假失败。
- `repro_*.py` 是一次性复现脚本（如 `repro_danbooru_gallery_persistence.py`），属开发时工具，不是回归。
- 多个脚本**硬编码绝对路径** `E:\1AI\ComfyUI-aki-v3\...`（实测 `test_gallery.py`、部分 verify），换机器即废。

### B4 ⚠️ `__init__.py` 2657 行单一文件
内含（按 grep 归类）：**API routes（含 `/anima/version`、`/anima/update/apply`）、GitHub ZIP 更新链、更新文件白名单、
Civitai/LoRA 相关、代理探测、下载、Outputs/gallery 桥接、Prompt 相关、bridge、节点注册**。
风险：任何改动都在同一文件的 diff 里，冲突面最大；且**没有版本标记**，运行目录漂移时看不出来。

### B5 `data/` 里混着「运行时状态」被跟踪
`data/batches/bworker.json` 是批处理运行时状态（含 `state/updated` 时间戳），**却进了 git**：
任何跑过一次批处理的机器都会把它改脏（本轮工作区就有这个 diff，**不是我引入的**）。
`.gitignore` 只忽略了 `data/danbooru_account.json` 等少数文件，没有兜住 `data/batches/`。

### B6 自检工具自身的可用性缺陷（**已修**）
`ai_verify.py` 用 `❌`/`⚠️` → 默认 GBK 控制台下**只在有 FAIL 时崩溃**。已替换为 `[X]`/`[!]`。

3. ⬜ **CI 验证流程**：与 `Build panel app` **分开**，只读、不提交、不 push；`on: [push(main), pull_request]`；
   覆盖 `py_compile` + `ai_verify.py` + 分层后的 pytest + `tsc --noEmit` + panel build +
